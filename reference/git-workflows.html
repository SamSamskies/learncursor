Git Workflows

Three surfaces — SCM panel, git @ mentions, Agent + gh.

Git @ mentions

MentionAttachesUse when
@Commit (Diff of Working State) Uncommitted changes Draft commit message, pre-commit review, scope check
@Branch (Diff with Main) Full branch vs base (merge-base aware) PR description, branch review before push, Agent Review base

Former name: @PR (Diff with Main Branch) → now @Branch. Push the branch before using @Branch for PR drafting — un-pushed branches may only get a commit suggestion.

Three git surfaces

SurfaceBest for
SCM panel (Source Control) Stage, commit, push — fast, deterministic, no tokens
Agent + @Commit / @Branch Draft messages, review diffs, PR bodies, pre-push sanity check
Agent + gh Create PRs, read review threads — paste URL or let Agent run CLI

Commit rule (solo builder)

Verify green  →  review diff  →  commit (you or explicit ask)
Never let Agent commit silently — user rule + permissions.json rails.

Prompt templates

// Draft only — no git write
Review my uncommitted changes. Suggest a commit message.
Do not run git commit.
@Commit (Diff of Working State)

// PR body after push
Branch is pushed. Draft gh pr create as one line:
--title "feat: …" --body with ## Summary and ## Test plan
@Branch (Diff with Main)

// Pre-push review
Anything risky in this branch diff? List only blockers.
@Branch (Diff with Main)
