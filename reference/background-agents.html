Background Agents

Local parallelism — /multitask, subagents, worktrees

Three agent runtimes (recap)

RuntimeWhereReach for when
Foreground Agent Agents Window, your working tree Default — one task, you watch diffs
Background subagents Spawned by /multitask or Plan "Build in Parallel" Independent chunks; keep chatting while work runs
Cloud Agent Ubuntu VM, fresh clone Long runs, close laptop, automations (ref)

/multitask triggers

  • Type /multitask before a prompt — parent may spawn subagents; decomposition is not guaranteed
  • Plan Mode → Build in Parallel — more reliable for independent plan steps
  • Worktrees — manual setup in Agents Window; only when parallel edits would overlap

Foreground vs background subagent

ModeParent blocks?Use when
Foreground subagent Yes — waits for result Parent needs output before continuing
Background subagent No — returns immediately Parallel workstreams; long research or shell tasks

Worktrees — isolation for parallel edits

Without isolation, two subagents editing the same checkout can conflict. Worktrees give each background task its own branch + filesystem copy. Promote to foreground when ready to test.

  1. Agents Window → worktree for a branch
  2. Run isolated task in background
  3. One-click move branch into local foreground to verify

When to use /multitask

Good fitPoor fit
Two unrelated fixes (API + CSS) One coherent refactor touching same files
Research + implementation in parallel Step B depends on Step A's output
Queued prompts you don't want to wait on Small one-file change — overhead not worth it

Solo-builder moments

MomentSurface
Bugbot comment + unrelated doc fix /multitask — two parallel subagents
Plan with 3 independent slices Build in Parallel
Experiment on branch A while B runs tests Worktree per branch
Overnight / close laptop Cloud Agent, not local background

Guardrails

  • Verify each subagent's diff yourself — parallel ≠ auto-reviewed
  • Stack with verify loop and hooks; background subagents still hit local hooks
  • Overlapping file edits → use worktrees or serialize
  • Cloud agents have no local hooks — different risk profile
