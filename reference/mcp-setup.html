MCP Setup

Project file for shared tools. Global file for personal ones.

Config locations

PathScope
.cursor/mcp.json This repo only — commit to git (no secrets)
~/.cursor/mcp.json All workspaces on your machine

Same server name in both? Project config wins.

Stdio server template

{ "mcpServers": { "server-name": { "command": "npx", "args": ["-y", "@org/mcp-server-package"], "env": { "API_KEY": "${env:API_KEY}" } } } }

Remote server template

{ "mcpServers": { "remote-api": { "url": "https://mcp.example.com/mcp", "headers": { "Authorization": "Bearer ${env:API_KEY}" } } } }

Interpolation variables

SyntaxResolves to
${env:NAME}Environment variable
${workspaceFolder}Project root (folder with .cursor/)
${userHome}Your home directory

Setup loop

  1. Create .cursor/mcp.json with one server
  2. Set secrets in shell or .env (gitignored)
  3. Developer: Reload Window
  4. Settings → Tools & MCP → confirm connected
  5. Prompt Agent with a task only that tool can do

Common solo-builder picks

ServerPackage / notes
GitHub @modelcontextprotocol/server-github + GITHUB_PERSONAL_ACCESS_TOKEN
Playwright @playwright/mcp — browser verify from Agent
Supabase @supabase/mcp-server-supabase + access token

Security checklist

  • Never commit tokens — use ${env:…}
  • Install trusted servers only; read what tools they expose
  • Fewer servers = less context noise and smaller attack surface
