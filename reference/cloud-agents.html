Run lifecycle

Trigger / prompt → VM boot → install (npm install) → agent loop → PR / comment / summary

What the run log shows

Visible on PASSMeaning
Environment readyBoot + install succeeded (collapsed when cached)
Results tableCommands run, summarized — not full stdout
Skill path in transcriptCommitted skill was discovered

Where to dig deeper

  • Environment name — hover repo link on run page, or Dashboard → Environments
  • Install script — on environment config page, not every run log
  • Raw shell — expand Environment ready; failures show more than passes
  • Intervene: follow-up message or remote desktop control

When to use which

Use localUse cloud
Active iteration, reading diffs, hooks, local MCP Long tasks, away from keyboard, scheduled verify
Playwright MCP browser verify PR opened → review while you sleep
Quick fixes, Plan Mode Multi-hour refactors, CI autofix on agent PRs

Debugging failed runs

  1. Read install step — did npm install fail?
  2. Check environment warning banner — snapshot expired?
  3. Confirm repo + branch match what you pushed
  4. Verify secrets in dashboard if tests need API keys
  5. Re-run manually with narrower prompt to isolate

Automations = cloud agents

Automations are cloud agents with a trigger + optional tools (Slack, PR comment, memories). Same VM, same environment, same run log UI. See Automations reference.
