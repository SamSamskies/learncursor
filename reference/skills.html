Agent Skills

Reusable workflows. Rules are always-on; skills load on demand.

LayerWhatWhen loaded

Storage locations

PathScope
.cursor/skills/name/SKILL.md This repo — commit to git
~/.cursor/skills/name/SKILL.md All workspaces — personal
.agents/skills/name/SKILL.md Also discovered (compat path)

Progressive loading

1. Discovery — name + description always available 2. Activation — full SKILL.md when task matches or you invoke 3. On demand — references/, scripts/ read only during execution

SKILL.md template

--- name: habit-tracker-ship description: Run the habit tracker verify loop after a feature change. Use when shipping, verifying, or finishing work on the habit tracker API or UI. --- # Habit Tracker Ship ## Verify checklist - [ ] npm test - [ ] npm run dev — smoke UI - [ ] npx playwright test (if e2e exists) ## Done when All checks pass. Report failures with command output.

Rules vs skills — when to use which

Put in rulesPut in skills
Stack choice (TypeScript, Drizzle)Multi-step ship / verify workflow
Formatting and naming prefsPR review checklist for a repo
"Run tests before done" (soft)Deploy-to-staging procedure
Always true in this projectRun sometimes, on explicit trigger

Authoring checklist

  1. One skill = one workflow (not a dump of all prefs)
  2. Description includes words users actually type
  3. Keep SKILL.md under ~500 lines; link to reference files
  4. Optional scripts/ for repeatable commands
  5. Commit project skills; keep secrets out of skill files
