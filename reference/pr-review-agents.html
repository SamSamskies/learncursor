PR Review Agents

Bugbot → Security Agents → Approval Agents — one pipeline, three layers

Pipeline
Local /review → open PR → Bugbot on GitHub → Security Reviewer (optional) → Approval Agent (team) → merge

Three agents compared

AgentFocusWhere it runsSolo builder?
Bugbot Bugs, quality, some security GitHub PR + local /review-bugbot Yes — individual usage billing
Security Agents Vulnerabilities, threat model Automations (PR or cron) + /review-security Local skill yes; cloud automations team-billed
Approval Agents Auto-approve or route reviewers PR triggers on team repos Team feature — know the pattern

SkillReviews

Same diff reviewed locally → Bugbot on GitHub skips duplicate review (patch ID sync).

Bugbot on GitHub

  • Auto on each PR push (configurable: mention-only, once per PR, incremental)
  • Manual: comment cursor review or bugbot run
  • Check: Cursor Bugbot — success = clean; neutral = findings (default)
  • Rules: .cursor/BUGBOT.md (nested paths supported)
  • Autofix: cloud agent pushes fix branch or same branch (on-demand billing)

Security Agents (two types)

TypeTriggerUse for
Security ReviewerPR opened / updatedBlock vulns before merge
Vulnerability ScannerCronFind old issues at rest

Approval Agents (team)

  • Waits for Bugbot + Security checks when enabled
  • Findings needing human review → no auto-approve
  • Policy files: APPROVAL_POLICY.md (per directory), .cursor/approval-policies/ROUTING.md
  • Conflicts → stricter policy wins; policy edits in PR → human review

Solo substitute for Approval Agents

  1. /review locally before push
  2. Open PR → read Bugbot comments
  3. Fix → push → re-run verify
  4. You click merge when checks + maintainer feedback are green
