OSS Workflow

Explore first on unfamiliar code. Point Agent only after you know where.

Five phases

  1. Pick — small issue, stack you recognize, active repo
  2. Clone — fork if required; open folder in Cursor
  3. Explore — Agent without @; read CONTRIBUTING + run their test command
  4. Change — Agent + @ for 1–3 files; Plan Mode if slice spans many layers
  5. Verify — their test/lint commands green; open PR with issue link
  6. Review — triage comments; fix little; re-verify; reply on threads (PR Review Loop)
  7. Hand off — re-request review; wait; one polite ping if needed (PR Merge Etiquette)

Explore prompts (no @ needed)

I want to fix: https://github.com/owner/repo/issues/42 Title: [paste title] Description: [paste key details] How is this repo structured? Where should I start? What does [function/module] do? Who calls it? How do I run tests locally per CONTRIBUTING?

Implement prompts (after explore)

Fix: https://github.com/owner/repo/issues/42 Summary: [one sentence from issue] Scope: only files needed for this fix. Done-when: [their test command] green; no unrelated refactors.

Surface picker (OSS)

SituationReach for

Bug in one known file Agent + @that-file
Feature touching 4+ files you don't own Plan Mode — review before Build
Typo or one-liner after you found the line Inline Edit (Cmd+K)

Red flags → stop and revert

Agent did thisWhy it's wrong
Renamed unrelated files OSS maintainers reject drive-by refactors
