Project Rules

Persistent instructions so Agent remembers your stack and habits

Three layers (solo builder)

Layer Where Use for
User Rules Cursor Settings → Rules Preferences on every project — tone, commit style, "don't commit unless asked"
Project Rules .cursor/rules/*.mdc Stack, architecture, test patterns — version-controlled per repo
AGENTS.md Project root (or subdirs) Simple markdown instructions when you don't need rule types or globs

Rule apply modes (.mdc)

Mode When it loads
Always Apply Every Agent chat in this project
Apply Intelligently Agent reads description and pulls it in when relevant
Apply to Specific Files When a matching file is in context (globs)
Apply Manually When you @-mention the rule in chat

Minimal .mdc template

---
description: Express + SQLite API conventions for this project
alwaysApply: true
---

- Express server; sqlite3 for persistence (no ORM)
- Every feature ships with an npm test that seeds data and hits the endpoint
- Run `npm test` as the done-when check before accepting a diff

When to add a rule

Add a rule when you repeat the same Constraints in two or more prompts, or when Agent makes the same mistake twice. Start with one short rule; split later if it grows past ~500 lines.

What rules do not affect

Rules apply to Agent (Chat) only — not Tab completion or Inline Edit (Cmd+K).
