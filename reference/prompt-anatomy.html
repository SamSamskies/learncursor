Prompt Anatomy

Four parts every solo-builder Agent prompt should have

Part Ask yourself Example
Goal What should exist when done? "Add a habit list page that loads from localStorage"
Scope What is in / out this turn? "Only the list view — no edit flow yet"
Constraints What rules must Agent follow? "Vanilla HTML/CSS/JS, no new dependencies"
Done-when How will you verify it works? "Run a local server; I can add and see habits"
Goal: [one concrete outcome] Scope: [in this message / not in this message] Constraints: [stack, style, files to touch or avoid] Done-when: [command to run or behavior to check]

@ mentions

When What to attach
You know the file @src/auth.ts or @src/components/
Debugging a failure @Terminals for command output
Reviewing your changes @Commit or @Branch diff
You don't know where the bug lives Skip @ — describe the symptom; Agent searches

Anti-patterns

  • Kitchen sink — three features in one prompt
  • Vague goal — "make it better" with no done-when
  • Over-attach — @ every file when Agent should search
  • No verify step — Agent finishes but you never run it
