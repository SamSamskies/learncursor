YOLO Mode (Run Modes)

Speed without supervision is how you rm -rf a Tuesday. Auto-run with rails is how you ship by lunch.

Every time Agent runs npm test, you click approve. Every mkdir, another click. That friction kills the solo-builder loop from Lesson 4 — Agent should run your verify command, read the output, fix, and repeat without you babysitting the terminal.

YOLO mode is the old community name for letting Agent run commands without asking. In Cursor 3.6+ it lives under Run Modes in Settings → Agents → Approvals & Execution. The modern default is Auto-review — not zero prompts, but far fewer than clicking every time. Keep the Run Modes reference open.

Three modes (pick consciously)

ModeWhat auto-runsSandboxSolo builder
Auto-review Allowlisted + sandboxed commands; classifier reviews the rest Yes Start here — recommended default
Allowlist Only commands you explicitly list Optional When you want a tiny, fixed command set
Run Everything Every tool call, zero prompts No Old YOLO — fast, risky; trusted repos only

Primary source: Run Modes — official docs. Cloud agents ignore Run Modes — they run in their own VM (Lesson 14).

How Auto-review decides

1. Allowlist Commands you've pre-approved run immediately
2. Sandbox Supported shell commands run in a restricted environment — limited file/network reach
3. Classifier Everything else gets an LLM safety review — allow, block, or ask you

The classifier is not a security boundary — it can misjudge. That's why you stack Run Modes with hooks from Lesson 11 and your verify loop from Lesson 4. Run Modes control when Agent asks; hooks block specific actions deterministically; you still read diffs before accepting.

Run Modes vs hooks vs verify

LayerJobExample
Run Mode Reduce approval clicks Auto-review sandboxes npm test
Hook Hard block on shell events Deny git push --force to main
Verify loop You confirm done-when Run npm run verify yourself before merge

Steer Auto-review with permissions.json

Tell Cursor in plain English which commands should lean toward approval or blocking. Per-project file — commit it so every session inherits the policy: 

{
  "autoRun": {
    "allow_instructions": [
      "npm test and npm run verify are safe to auto-run."
    ],
    "block_instructions": [
      "Every git push --force should require my approval.",
      "Every command that drops database tables should require approval."
    ]
  }
}

Path: .cursor/permissions.json in your active repo. Cursor merges it with ~/.cursor/permissions.json if both exist. You can also ask Agent: "Add block instructions for force-push to my permissions.json."

Built-in protections still apply.
Even in Run Everything mode, Cursor blocks auto file deletion, writes outside the workspace, and browser tools unless you override. Hooks add project-specific gates on top.

When to reach for true YOLO (Run Everything)

SituationReach for
Greenfield throwaway spike in a sandbox dir Run Everything — speed over safety
Active app repo with git history (habit tracker, LocalLab) Auto-review + hooks + verify loop
Agent keeps asking for the same three commands Allowlist those commands, or add allow_instructions
Agent hangs after running a command Legacy Terminal setting; simplify zsh prompt when CURSOR_AGENT is set

Terminal troubleshooting: Terminal docs — heavy shell themes (Powerlevel10k) can break command-completion detection.

Do this now

Auto-run your verify loop on a repo you actively build — habit tracker or LocalLab.

  1. Check your mode — Settings → Agents → Approvals & Execution. Confirm Auto-review (or note what you're on).
  2. Add permissions.json — create .cursor/permissions.json with at least one block_instruction for destructive git (see example above). Commit it.
  3. Count clicks — open Agent on that repo. Prompt: Run npm run verify (or npm test). If anything fails, fix it and re-run until green. Do not change unrelated files. Count how many times Cursor asks you to approve a command.
  4. Compare — if you still get excessive prompts for the same safe commands, add an allow_instruction for your verify script.
  5. Stack hooks — if you already have a force-push gate hook (Lesson 11), confirm it still fires under Auto-review.

You are done when Agent runs your verify command with zero or minimal approval clicks, and you still read the diff before accepting.
