Set Up Project Rules

A good prompt tells Agent what to do once. A good rule tells Agent how this project works forever.

In Lesson 2 you wrote a four-part prompt for step 1 of your Express plan — stack, sqlite3, test with npm test. That's the right shape. But you'll repeat those Constraints on every plan step unless you write them down once as a project rule.

Rules are persistent instructions Agent loads automatically. They turn repeated prompt boilerplate into project memory — exactly what solo builders need when jumping between repos. (Mission: "set up project rules once.")

Three layers

User Rules Global preferences in Cursor Settings → Rules. "Don't commit unless I ask." Applies to every project.
Project Rules Files in .cursor/rules/*.mdc, checked into git. Stack, architecture, test patterns for this repo.
AGENTS.md Plain markdown in the project root. Simpler alternative when you don't need apply modes or globs.

Keep the project rules reference handy. For your Express app, start with one Always Apply project rule — not a pile of rules on day one.

Before rules vs after

Every prompt — you repeat Constraints
Goal: Add POST /habits endpoint.
Scope: Create route + db migration only.

Done-when: Run npm test — all green.
Rule handles Constraints — prompt stays thin
Goal: Add POST /habits endpoint.

Start simple — official guidance
Add rules only when Agent repeats a mistake or you repeat the same constraints twice. Cursor docs warn against copying entire style guides — point to examples instead.

A starter rule for your Express project

Create .cursor/rules/express-api.mdc in the repo where you built step 1:

---
description: Express + SQLite API conventions for this project
alwaysApply: true
---

- Express server; sqlite3 for persistence (no ORM unless I ask)
- Seed test data in tests, not in production startup
- Every new endpoint ships with an npm test that hits it
- Run `npm test` as the done-when check before accepting a diff

Or type /create-rule in Agent and describe what you want — Agent writes the file for you.

Check your understanding

2. You want rules only when editing test files. Best mode?
