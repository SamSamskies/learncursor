Lesson 4 · ~8 minutes

Verify and Iterate

Agent finished. That doesn't mean you're done — it means your review starts now.

In Lesson 3 you sent a thin prompt for POST /habits and Agent followed your express-api rule without you repeating Constraints. That's the build half of the loop. This lesson is the other half: verify the diff, then pick the right fix when something's off.

AI code can compile, pass tests, and still be wrong — wrong scope, wrong patterns, or tests that check the wrong thing. (Mission: you still need to read diffs.)

Three checks before you accept

1. Scope Did Agent touch only the files you asked for? Extra refactors or surprise dependencies are a yellow flag.
2. Patterns Does the diff match your project rule? sqlite3 not an ORM, test seeds data, endpoint has a test.
3. Done-when Run your verification yourself — npm test, open the app, curl the endpoint. Don't trust Agent's "all tests pass."

Keep the verify loop reference open while you work.

While Agent is still running

Stop early
Watch the diff stream. If Agent opens the wrong file or heads in a bad direction, click Stop or press Cmd+Shift+Backspace. Revert and refine your prompt — don't wait for a full bad build.

When something fails — pick the surface

SituationSurface
One typo or off-by-one in a single function Inline Edit (Cmd+K) on the selection
Wrong approach, missed files, or tests still red after one fix New Agent chat — refined Goal + Scope + Done-when
Agent ignored your project rule New chat — quote the rule bullet it missed + paste the failing output
Entire plan step went sideways Revert the diff, go back to Plan Mode, refine the step

Fix prompt shape (when tests fail)

Goal: Fix POST /habits — test "creates habit" returns 201.
Scope: Only routes/habits.js and tests/habits.test.js.
Done-when: npm test — all green.

Failing output:
  Expected 201, got 500
  at tests/habits.test.js:14

Paste the actual error. Agent fixes faster with evidence than with "it's broken."

Check your understanding

1. Agent says "all tests pass" but you haven't run them.

2. One assertion is wrong in a test file Agent wrote.

3. Agent added a Postgres driver despite your sqlite3 rule.

Do this now

5-minute win in your Express habit-tracker project.

No errors required. Most diffs pass — the skill is checking anyway, not fixing.

  1. Retrospective check — open the POST /habits diff. Ask: did Agent touch only route + migration files? Does it match your express-api rule (sqlite3, seeded test data, endpoint has a test)?
  2. Run done-when yourself — npm test in the terminal. You run it; don't rely on Agent saying tests passed.
  3. If all green → move on. Pick the next step from your habit-tracker plan (e.g. GET /habits, DELETE /habits). Send a thin prompt — Goal + Scope + Done-when only. When Agent finishes, repeat steps 1–2 on that diff.

That's the loop: build → scope check → pattern check → run tests → next step. You're done with this lesson once you've verified one diff and started the next plan step with the three checks.

Optional stretch: draft a fix prompt for a hypothetical failure (paste a made-up error). Useful later — skip if everything is green.
