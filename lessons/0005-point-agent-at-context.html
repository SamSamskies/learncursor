Lesson 5 · ~8 minutes

Point Agent at Context

Rules carry your conventions. @ mentions carry your codebase. Together they make thin prompts actually work.

In Lesson 4 you verified TypeScript and Drizzle migrations yourself — scope, patterns, done-when. That's the review half. This lesson is about the build half: telling Agent exactly which files to read before it starts guessing.

Project rules say how to build (TypeScript, Drizzle, npm test). @ mentions say where to look (this route, this schema, this test). (Mission: clone an unfamiliar repo and contribute — you can't @ a file you haven't found yet.)

Common @ mentions

TypeWhen to use
@filename You know the exact file — route handler, Drizzle schema, test file.
@folder/ A whole layer — @src/routes/ or @tests/.
@Codebase Unfamiliar repo — "where is routing set up?" before you know paths.
@Docs Framework API Agent should follow — Drizzle queries, Express middleware.
@Web Current docs or a specific error page not in your repo.

Keep the @ context reference open while you work.

Decision rule

Know the file?     → @file
Know the area?     → @folder
Don't know either? → @Codebase first, then narrow on the next prompt
Less is more
Attach 2–4 files that define the pattern — not the whole repo. Agent's context window is finite; every irrelevant file crowds out what matters.

Thin prompt + @ context

Your habit-tracker POST route already exists. Adding GET /habits should mirror it:

Goal: Add GET /habits — return all habits as JSON array.
Scope: Route + test only. No schema changes.
@src/routes/habits.ts @src/db/schema.ts @tests/habits.test.ts
Done-when: npm test — all green.

Rules handle stack conventions. @ mentions handle "copy this pattern." Then verify the diff as usual.
