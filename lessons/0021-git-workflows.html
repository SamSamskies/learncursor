The commit rule

Your user rule: Agent commits only when you explicitly ask. That is the right default for a solo builder — verify green, read the diff, then commit. Agent is great at drafting messages and spotting scope creep; the SCM panel (or an explicit "commit now" prompt) is where the write happens.

Verify Run done-when yourself — same loop as Lesson 4
Review @Commit for scope check or message draft — no git write
Commit SCM panel, or tell Agent explicitly: "Commit with this message"
Push + PR Push yourself; @Branch for PR body; run or approve gh pr create

Run Modes from Lesson 19 auto-run read-only git (status, diff) but git commit often still needs approval — or gets stuck on some builds. SCM panel avoids that friction entirely.

Do this now

Draft with @, commit with SCM — LocalLab, habit tracker, or this workspace.

  1. Branch + change — create a feature branch. Make one trivial, safe edit (comment, doc line, test name).
  2. Verify — run your done-when command if the repo has one; otherwise skip.
  3. @Commit review — Agent prompt: Review my uncommitted changes. Suggest a one-line commit message. Do not run git commit or git add. Add @Commit (Diff of Working State).
  4. Commit yourself — use the SCM panel (Source Control) with Agent's suggested message, or your own.
  5. Push + @Branch — push the branch. Prompt: Draft a single-line gh pr create command with --title and --body (## Summary, ## Test plan). Do not run it. Add @Branch (Diff with Main). Read the command — run it only if you want an open PR.

You are done when Agent reviewed via @Commit, you committed through SCM, and @Branch produced a sensible gh pr create draft.
