Debug Mode & Persistent Context

Agent guesses from static code. Debug Mode waits for runtime proof.

You have shipped apps, reviewed PRs, and stacked rules, hooks, skills, and automations. Two topics remained on the post–Lesson 18 checklist — Custom Modes and Memories — but Cursor removed both in version 2.1. This lesson closes the gap honestly: the fourth built-in mode you have not practiced yet (Debug), and the persistence stack you already use instead of IDE memories.

Switch with Shift+Tab or the mode picker. Each mode starts a fresh context window — new chat when you change tasks (Agent modes).

What Debug Mode does differently

Standard Agent reads code and proposes fixes. Debug Mode follows a runtime-evidence loop from official docs:

Hypothesize Explore files; list multiple possible causes
Instrument Add log statements → local debug server (Cursor extension)
Reproduce You run the steps; agent captures real runtime data
Analyze + fix Read logs; small targeted patch; verify; remove instrumentation

Pairs with @Terminals from Lesson 20 — Debug is the structured version when Agent's guess-and-check loop stalls on a bug you can reproduce.

Do this now

Debug one real bug — habit tracker or LocalLab.

  1. Pick a reproducible bug — failing test, wrong UI state, or a regression you can trigger reliably. If nothing is broken, temporarily break something small (e.g. invert one assertion) and note how to undo it.
  2. Switch to Debug — Shift+Tab until Debug appears. New chat recommended.
  3. Prompt with reproduction steps — include expected vs actual behavior, error output, and which command or click path triggers it. Let Debug instrument, then follow its reproduction steps exactly.
  4. Verify the fix — run your done-when command (npm test, npm run verify). Confirm instrumentation was removed.
  5. Capture one preference as a rule — if Debug surfaced something you want every future session to know (e.g. "always run e2e after dialog changes"), add one line to a project rule or user rule — not a chat memory.

You are done when Debug found root cause via runtime evidence, tests are green, and one preference lives in rules — not chat.
