Terminal Integration

The terminal is not one thing. It is three surfaces — and picking the right one keeps Agent fast without fighting your hooks.

Lesson 19 let Agent auto-run your verify commands. But where do those commands run? In Cursor's integrated terminal. When do you open Terminal.app instead? When do you reach for the agent CLI? This lesson ties terminal surfaces to the workflows you already use — verify loop from Lesson 4, hook testing from Lesson 11, and @ context from Lesson 5.

Keep the Terminal Integration reference open.

Three terminal surfaces

Integrated terminal — Agent's home base

When Agent runs npm test, output appears in Cursor's integrated terminal panel. Your Run Mode from Lesson 19 controls whether it asks first. The sandbox restricts file and network access for supported commands.

Watch Open the terminal panel while Agent works — catch hangs and truncated output early
Verify Run done-when yourself after Agent finishes — don't trust "tests passed" alone
Attach Type @Terminals in chat to send terminal output as context

Official prompting guide lists @Terminals alongside @filename and git diffs — Prompting agents. Use it when a command already failed and Agent needs the exact stack trace, not when you want Agent to discover the problem from scratch. 

This test failed in my terminal. Fix only the failing test.
@Terminals
Done-when: npm test — all green.

External terminal — when Cursor gets in the way

Lesson 11 taught a pattern worth repeating: test hook scripts in Terminal.app before wiring hooks.json. Once a beforeShellExecution hook is live, it intercepts matching commands in the integrated terminal too — including innocent test lines that happen to contain git push --force.

TaskTerminal
Pipe sample JSON into a hook script External — before hooks.json exists
Run npm run verify yourself after Agent Either — your call
Agent auto-runs verify under Auto-review Integrated — Agent drives it
Debug why a hook blocked Agent External — reproduce without Agent in the loop
Truncated or garbled output?
Heavy shell themes (Powerlevel10k) break Agent's command-completion detection. Set CURSOR_AGENT in your shell config to skip the theme when Cursor runs. Full fix in Run Modes reference and Terminal docs.

Cursor CLI — Agent outside the editor

The CLI installs a single command — agent — that shares your Cursor account, rules, skills, and MCP config with the editor. Same modes; different shell. 

# Install once (macOS)
curl https://cursor.com/install -fsS | bash

# Interactive — approve edits and commands in the shell
agent
agent "fix the failing test in tests/habits.test.ts"

# Plan mode from the terminal
agent --mode=plan "add export to CSV endpoint"

# Headless — scripts, cron, CI (read-only example)
agent -p "list open TODO comments in src/" --output-format text

# Headless with file writes (use carefully)
agent -p --force "fix eslint errors in src/routes/"

Interactive (agent) mirrors the editor chat: you approve commands and review diffs. Print mode (-p) sends output to stdout — for automation. Add --force only when a script should apply file changes without manual approval.

Resume prior sessions with agent ls and agent resume. Cloud handoff works too — prepend & to a message to push work to a cloud agent (Lesson 14).

Do this now

Debug with @Terminals, then peek at the CLI — habit tracker or LocalLab.

  1. Break something on purpose — in the integrated terminal, run your verify command (npm test or npm run verify) after introducing a trivial typo in a test file (or pick an existing failure).
  2. Attach output — open Agent. Prompt: Fix the failing test shown in my terminal. Change only what's needed. Add @Terminals. Confirm Agent sees the exact error.
  3. Verify yourself — run done-when in the integrated terminal after Agent fixes it.
  4. Check the CLI — in an external terminal, run agent about (or agent status). If not installed: curl https://cursor.com/install -fsS | bash.
  5. One headless read — from the repo root: agent -p "How many test files are in this project? Reply with a number only." --output-format text. No file changes — just confirm the CLI sees the repo.

You are done when Agent fixed the failure using @Terminals, you ran verify green yourself, and agent about returned your account info.
