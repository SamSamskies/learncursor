Capstone: Fresh App in One Session

Fifteen lessons taught you the pieces. This lesson makes you run the whole machine once, from scratch.

You built habit tracker slice by slice across Lessons 5–7, then layered rules, hooks, skills, automations, cloud verify, and Bugbot on top. That was the right way to learn each tool. The mission's first success criterion is different: start a new idea and reach a working first version in one focused session. This capstone is that session. Keep the Fresh App Workflow reference open — it is your checklist.

Not another habit tracker.
Pick a small new idea. Copy patterns from habit tracker (TypeScript, Drizzle, verify loop), not the repo itself. The win is proving the workflow transfers.

What "working first version" means

Borrowing from Lesson 7: one core user action works end-to-end in a browser (or CLI if the app is CLI-only). Tests or a verify command pass. You can demo it to someone in under a minute. Everything else — auth, polish, deploy, hooks, automations — is after the capstone.

In scopeOut of scope (add later)
Plan → scaffold → core API/data → minimal UI → verify Production deploy, OAuth, mobile apps
Project rules in .cursor/rules/ Hooks, skills, automations (you know how — skip for speed)
Local /review-bugbot before push Cloud environment.json (unless you want cloud agents day one)
Optional: BUGBOT.md with one rule Full design system, e2e suite (one smoke test is enough)

The six phases

Phase 1 — Spark (5 min)

Write one sentence: who uses it, what problem, one core action. Then cut until it fits ~2 hours. 

Bad:  "A social network for pet owners with messaging and maps."
Good: "I log one mood per day and see a seven-day streak in the browser."

Starter ideas if you are stuck: daily mood log, bookmark saver, simple expense tracker, pomodoro timer with history, recipe box with search.

Phase 2 — Plan (20–30 min)

Open a new empty folder. Switch to Plan Mode. Lock Opus or GPT-5.x — not Auto (Plan Mode reference). 

Plan a [your one-sentence app].

Constraints:
- Solo builder, single session (~2 hours build time after plan)
- Stack: TypeScript, [pick: Express + Drizzle + SQLite | Next.js app router | your choice]
- First slice: one core CRUD or action + minimal UI to demo it
- Include: folder layout, verify command (npm test or npm run verify), what "done" means

Ask me questions before you finalize the plan.

Read the plan like a PR description. Push back on scope creep. Click Build only when the verify command and first slice are explicit. Check the model dropdown — it may reset to Auto after Build.

Phase 3 — Bootstrap (15–20 min)

First build pass should produce:

  • Git init + .gitignore
  • .cursor/rules/ — stack, test command, "read diffs" reminder (Lesson 3)
  • Scaffold matching the plan
  • Initial commit

Reuse your habit tracker rule structure if helpful — you are not cloning the repo, just the pattern of what belongs in rules.

Phase 4 — Build + verify (45–60 min)

Implement the plan's first slice one step at a time. After each meaningful change, run the verify loop:

  1. Run tests / verify command
  2. Read the diff — does it match intent?
  3. Fix failures before asking for the next feature

Use @ mentions to point Agent at the right files (Lesson 5). Tab and Inline Edit for typos — Agent for multi-file work (Lesson 1).

Phase 5 — Ship the slice (30–45 min)

Add the thinnest UI that proves the core action works — same bar as Lesson 7. Open the app in the browser. Click through the happy path yourself.

Optional: if Playwright MCP is installed, ask Agent to smoke-test the happy path (Lesson 10). Do not let e2e setup eat the session — manual click-through counts.

Phase 6 — Review + push (10–15 min)

Run /review-bugbot on branch changes (Lesson 15). Fix valid findings. Optional: add .cursor/BUGBOT.md with one repo-specific rule. Push to GitHub. Open a PR if you want remote Bugbot — you already know the patch-ID sync trick from lesson 15.

When you get stuck

SymptomReach for
Agent keeps breaking unrelated files Narrower prompt + @ specific files; smaller slice
Tests fail and Agent loops Paste error output; say "fix only X, do not refactor"
Scope ballooning Re-read Phase 1 sentence; defer everything not in it
Plan Mode wants too much "Remove Y and Z from v1 — only ship [core action]"
2 hours gone, no UI Skip polish; ship read-only list + one write action

Do this now

Run the full workflow on a new app idea

  1. Spark — write your one-sentence pitch. Reply to your agent teacher with it if you want a scope check.
  2. Plan — new folder, Plan Mode, frontier model locked. Approve plan with explicit verify command.
  3. Bootstrap — scaffold + .cursor/rules/ + initial commit.
  4. Build + verify — first slice only. Green tests before UI.
  5. Ship slice — minimal UI, manual happy-path demo.
  6. Review — /review-bugbot, fix findings, push (PR optional).

You are done when you can demo the core action in a browser, tests pass, rules are committed, and you ran local Bugbot review. Tell your agent teacher the repo URL and what you would add in session two.
