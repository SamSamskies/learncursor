What /multitask does

In the Agents Window, type /multitask before your prompt (or ask Cursor to multitask on messages already queued). Instead of running prompts one-by-one, Cursor spawns async subagents — each with its own context window — and returns summaries to the parent chat.

Queue parallelization Three stacked prompts → three subagents at once, not three waits
Auto-decomposition One large prompt → Cursor splits independent chunks across a fleet
Build in Parallel Plan Mode alternative — independent plan steps run simultaneously

Each subagent only returns a summary to the parent — your main context stays free for planning and review. Built-in subagents handle research, shell, and browser work; the parent coordinates.

Worktrees — isolation when edits overlap

Background subagents editing the same checkout can step on each other. Worktrees give each task its own branch and filesystem copy inside the Agents Window. Run isolated work in the background; when ready, promote the branch to your local foreground with one click and verify there.

SituationIsolation
Research-only subagent (no file edits) None needed
Two fixes in different directories /multitask often fine on one checkout
Two features touching same files Worktree per branch — or serialize

Do this now

Parallelize two independent slices — habit-tracker PR #2 is a ready-made pair.

  1. Checkout the branch — git checkout add-delete-confirmation on habit-tracker (or any repo with two unrelated todos).
  2. Queue two prompts — in the Agents Window, draft two independent requests. Example A: Fix Bugbot issue: guard confirmDelete so a second call while the dialog is open returns the existing promise. Verify with npm test. Example B: Add a one-line comment above confirmDelete explaining the re-entry guard. No logic changes.
  3. /multitask — type /multitask and send both (or ask Cursor to multitask on the queued messages). Watch the sidebar for separate subagent runs.
  4. Review each diff — read both summaries; inspect file changes separately. Run npm test and npm run test:e2e yourself.
  5. Commit via SCM — one commit for the guard fix; optional second commit for the comment. Push to update PR #2.

You are done when two subagents finished in parallel, you verified green, and PR #2 reflects the Bugbot fix.
